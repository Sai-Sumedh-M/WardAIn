# Decisions
- dashboard/app.py: Phase 1 placeholder so all 4 compose services start; replaced in Phase 5
- scenarios/runner.py: --engine flag is parsed but only the plain engine exists until Phase 5b; scorecard call added in Phase 3
- gateway/store.py: approvals table has no status_code column, so response_json stores {"status_code", "response"}
- gateway/pipeline.py: compensation rows (step 13, ON only) are written in Phase 4 together with rollback
- gateway/app.py: GET /approvals/{id} only validates the bearer token (no envelope, no ownership check), as specified
- scenarios/attacks.py: RogueClient takes an optional httpx client (for tests) and exposes mint_jwt/send helpers
- scripts/dev_local.sh: sources .env (set -a) before the local URL/DB overrides so gateway and runner share ADMIN_TOKEN
- agents/admin.py: AdminClient raises AdminError (method, path, status code, body) on non-2xx instead of returning error JSON
- gateway/store.py: get_events returns the most recent <limit> events (ascending) when since_ts is absent or 0; with since_ts > 0 it returns the oldest events after it, so polling works
- CLAUDE.md synced with Phase 1-2 fixes; also applied to .env.example, docker-compose.yml (healthchecks), gateway/llm.py (quote strip) and scenarios/runner.py (wait_for_gateway)
- gateway/monitor.py: Phase 3 holds only CircuitBreaker (app.state.circuit); Monitor rules arrive in Phase 4
- gateway/monitor.py: tools 4xx counts as a success for the circuit breaker; only unreachable or >=500 counts as failure
- gateway/pipeline.py: llm input messages are sanitised in the pipeline (ON only) rather than inside LLMBackend, so the events can be emitted
- gateway/pipeline.py: guards (step 5) run before the approval is created; an approved call then runs steps 6-18 only, without re-running guards
- gateway/chaos.py: `times` is counted per (run_id, rule); the RNG is only drawn when probability < 1.0
- scenarios/runner.py: tool_state_summary stores every ground-truth value (the expect vocabulary) plus payment/outbox counts, so the scorecard does not depend on a scenario's expect keys
- agents/workflow.py: exfiltrate mode implemented in Phase 3 (needed by pii_exfiltration); compromise mode waits for Phase 4
- scenarios: tool_outage is also 3/3 successful with WardAIn OFF, because the client's retry window (about 4.6 s) outlasts the 1.5 s outage
- gateway/monitor.py: R1 counts block events since max(now-30s, agent registration time), so blocks from earlier scenario iterations (same agent ids, events are kept across resets) do not quarantine a fresh agent
- gateway/pipeline.py: handle_call wraps the chain and runs the monitor (step 17) for every response except 400/401, so unauthenticated callers cannot trigger quarantine of a victim agent
- gateway/recovery.py: recovery_status.quarantined_agents lists agents with steps in the run whose current status is quarantined
- agents/workflow.py: if a compromised executor hits a non-quarantine agent_not_active block (paused/halted) it just stops the malicious sequence and continues
- dashboard/app.py: Run scenario launches the runner with sys.executable (the dashboard's own interpreter) instead of the literal "python"; engine radio offers only plain until Phase 5b
- dashboard/app.py: inserts the repo root into sys.path so `.venv/bin/streamlit run dashboard/app.py` can import agents/common without PYTHONPATH
- README.md: Phase 6 real-model run was done with the gateway started manually (LLM_MODE=nvidia), since dev_local.sh sources .env which sets mock
- agents/workflow.py: PLANNER_PROMPT embeds the canonical plan for C999/10.0 and says plan_index starts at 0; strict comparison unchanged (real model now gives llm_fallbacks=0)
- scripts/dev_local.sh: LLM_MODE_OVERRIDE (applied after sourcing .env) selects LLM_MODE; replaces the manual-start note above
- scripts: real-model raw output is kept in data/real_model/ (gitignored) so results/ holds only mock numbers
- scenarios/scorecard.py: kill_latency_ms is ON-only (OFF = n/a), since the kill-switch is not enforced in OFF mode
